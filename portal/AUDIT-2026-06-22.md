access enforced in `(console)/layout.tsx` via `profiles.staff_sections`.
⚠️ With a shared backing account, granular `staff_sections` only differentiates real users if each staff
gets their own Supabase login (the `team` module's `createStaffUser` path).

## 6. Data layer & the trade bridge

- 33 migrations applied live (28 forex-broker + the 06-20 staff batch). Note: the `00xx_*` Karochat
  migration files co-located in `supabase/migrations/` are **not** part of this broker schema.
- Core tables present: profiles, trading_accounts, wallets/wallet_transactions, kyc_documents, trades,
  signal_providers/copy_subscriptions/copy_trades, pamm_funds/investments/transactions, ledger
  (accounts/journal_entries/journal_lines), fee engine (schedules/rules/charges), commission_ledger +
  ib closure tree, support/chat, events_outbox, account_transfers, bridge_account_map, bridge_secrets.
- Deposits/withdrawals have **no dedicated tables** — modeled as `wallet_transactions` rows.

### How the bridge works (and its real status)
1. `bridge_account_map` maps a raptor account → portal trading_account + user.
2. `bridge_ingest_position(jsonb)` (service-role) idempotency-checks on `source_position_id`, inserts one
   `public.trades` row → fires `tg_trade_settled` / `tg_mirror_provider_trade` / `tg_pamm_apply_trade`.
3. `pg_cron` (every minute) `pg_net` POSTs to edge fn `raptor-trade-bridge`, which reads `raptor_url` +
   `raptor_service_key` + `bridge_secret` from `bridge_secrets`, pulls recent closed positions from the
   terminal project, and calls `bridge_ingest_position` per position.

**Verified status: the bridge is fully deployed and green** — edge fn ACTIVE, secrets populated, cron 200s.
**But it has ingested nothing new since the 28-trade backfill on 2026-06-17** — the terminal (a simulator)
isn't generating new closed positions, so Copy/PAMM/IB engines have real plumbing but no live trade flow.
(This corrects the earlier code-only assumption that the function "doesn't exist" — it's deployed but
the source isn't committed to the repo.)

1. **Reconcile migration drift** — dump the 7 live 2026-06-20 migrations back into `supabase/migrations/`

   `staff_sections` RBAC is meaningful.
